# 任务会话模型

## 为什么不能只用群 ID

一个执行群可能同时出现多个任务。即使消息来自同一个 Aily、同一个用户，A 和 B 也可能是两件完全不同的事；中间插入其他人的消息更不能作为“同一线程”的依据。

因此任务身份必须包含来源根消息/主题，并在执行群创建独立的根消息线程。

## 四种典型情况

| 场景 | 结果 |
|---|---|
| 同一根消息下的多个任务 | 同一个 `DS`，Aily 持久 FIFO，一次只派发队首一个 `T` |
| 同群两个独立根消息 | 两个 `DS`，两个执行线程，可并行 |
| 不同群的任务 | 默认两个 `DS`，相互隔离 |
| 同一 Aily 在不同群发任务 | 仍按来源群和根消息拆分，不共享会话 |

## 实施规则

1. Aily 收到新任务时，判断它是已有任务的续问还是新任务；有歧义先问人。
2. 新任务在执行群发送新的根消息，不要复用旧线程。
3. 当前运行 `T` 的补充信息可继续回复同一线程；独立新任务进入 Aily 队列，不提前 `@` 本地机器人。
4. 当前 `T` 终止后，Aily 才派发下一条；不同 `DS` 可同时运行。
5. 排队 `T` 由 Aily 直接取消；运行 `T` 才在对应线程发送 `/stop`。
6. 所有状态、审批和最终结果回复到该根消息线程。
7. 本地机器人不应根据自然语言标题合并会话。
