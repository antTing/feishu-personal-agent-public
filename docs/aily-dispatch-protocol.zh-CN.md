# Aily 任务分发协议

这是一份与具体上游产品无关的最小协议。Aily、Dify、Coze 或自定义机器人都可以按同样格式把本机任务交给 cc-connect。

## 分工

- 上游调度器负责判断是否需要本机、生成任务编号、维护来源会话映射、询问工作区/分支和转发最终结果；
- cc-connect 负责飞书长连接、线程会话、图片/普通文件接收、Codex 执行、进度和当前线程的停止；本项目固定版本补丁会让群内进度和终态引用并 `@` 原任务发送者；
- 安装器自动取得秘密和身份值；主人负责浏览器/飞书授权、工作区授权、Git 具体命令和工具审批；
- 执行群只作为三方可见的控制和结果回传区域，不作为任务身份的唯一依据。

## 任务链和任务编号

每条独立的来源对话链生成一个 `DS-XXXXXXXX`（任务链），链中的每个具体请求生成一个 `T-XXXXXXXX`（任务）。编号应由上游生成并持久化，不能根据消息标题或时间猜测。

建议使用以下逻辑键：

```text
任务链 = 上游智能体实例 + 来源群/私聊 + 来源根消息或明确主题
执行线程 = 执行群 + 新建的根消息
```

同一来源群里两个相互独立的话题必须生成两个 `DS`。不同来源群默认生成不同 `DS`。如果用户只说“继续”，但存在多个未完成任务，上游必须询问要继续哪个 `DS/T`。

## 封装格式

在发送给本地机器人消息中包含一个完整的 `[LOCAL_TASK]` 块：

```text
[LOCAL_TASK]
{"version":1,"chain_id":"DS-1234ABCD","task_id":"T-5678EFGH","workspace":"approved-workspace","permission":"read","branch":null,"request":"检查示例项目的构建配置","context":"只放本任务需要的背景"}
[/LOCAL_TASK]
```

字段说明：

| 字段 | 必填 | 说明 |
|---|---:|---|
| `version` | 是 | 当前为 `1` |
| `chain_id` | 是 | `DS-` 加 8 位大写字母/数字 |
| `task_id` | 是 | `T-` 加 8 位大写字母/数字 |
| `workspace` | 是 | 上游使用的公开别名，不是绝对路径 |
| `permission` | 是 | `read` 或 `development` |
| `branch` | 否 | 开发任务的已确认分支；未确认填 `null` |
| `request` | 是 | 当前任务，不复制无关历史 |
| `context` | 否 | 与当前任务直接相关的短背景 |

协议实现位于 `native/dispatch-envelope.mjs`，会拒绝坏格式、路径型工作区名称和过长输入。

该模块是给上游调度器复用的协议校验器，不是 cc-connect 内部 Router。cc-connect 不会根据 `workspace` 或 `permission` 字段自动切换目录、project 或模式。需要另一个目录时，Aily 保持暂停并通知主人；主人确认后使用原生 `/dir` 切换，再继续派发。

## 状态和停止

上游应保存：

```text
DS/T -> 来源会话、来源根消息、执行群根消息、执行线程、当前状态、派发消息 ID
```

状态至少包括：`accepted`、`queued`、`running`、`waiting_approval`、`stopping`、`finished`、`failed`、`cancelled`。

每个 `DS` 必须有上游持久 FIFO 和最多一个 `active_task_id`。上游只有在没有活动任务时才把队首 `T` 真正 `@` 给本地机器人；后续 `T` 保持 `queued`，可以在执行线程发布不带本地机器人 `@` 的排队通知。当前任务进入终态后再派发下一条。

停止排队 `T` 时，上游直接移出队列并标记 `cancelled`。停止运行中或等待审批的 `T` 时，上游先按映射找到执行线程，再在该线程明确 `@` 本地机器人，并发送正文仅为 `/stop` 的确定性控制消息。不得附加自然语言、任务编号或解释；应由固定工作流模板生成，而不是让模型自由改写。不要发送 `/cancel`：它会重置整条会话，也不要在共享群里无上下文地发送全局停止。当前原生 cc-connect 的停止语义是“当前线程会话”，不是跨线程全局编号 API。

## 工作区和分支门禁

未知工作区别名必须停在申请状态，不得把用户输入的绝对路径直接传给 Agent。主人核对本机目录后自行执行原生 `/dir`；Aily 不保存、猜测或发送绝对路径。需要创建或克隆目录时，仍先取得对应动作的明确授权。

开发任务在派发前询问目标 Git 分支。确认分支不等于批准 `switch`、`checkout`、`commit`、`merge`、`push` 等具体 Git 命令；每条命令仍需单独确认。没有 `.git` 的普通目录不应被当成错误，也不应强行初始化 Git。
