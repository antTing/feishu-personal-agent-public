# 从旧 Connector 迁移到原生 cc-connect

本文用于把已有的 `Feishu Connector -> Bridge -> cc-connect` 部署，分阶段迁移为 `飞书企业自建应用 -> 原生 cc-connect`。迁移目标是减少自维护链路，同时保留上游调度、任务隔离、主人审批、准确停止和结果回传。

## 迁移原则

- 先验证、后切流；原有服务在原生方案验收前保持可回退。
- 同一个飞书应用不能同时由旧 Connector 和原生 cc-connect 消费长连接事件。
- PoC 优先使用独立的测试飞书应用和测试执行群；若只能复用现有应用，切换前必须确认没有运行中或排队任务，并先停止旧服务。
- 不复制旧会话、日志、附件、密钥或运行缓存到新配置。
- 不在聊天、文档、截图或命令回显中暴露 App Secret、Token、飞书 ID、消息链接或完整个人路径。
- 所有 Git 命令、系统软件安装、配置覆盖、删除、开机自启动和网络暴露均需主人对具体动作明确批准。

## 阶段 0：记录基线

在不读取私有配置和日志正文的前提下，记录：

- [ ] 旧服务是否正在运行；
- [ ] 是否存在 `running`、`queued`、`waiting_approval` 或 `stopping` 的任务；
- [ ] 当前使用的飞书应用和执行群由主人自行确认；
- [ ] 当前已登记工作区别名及其 `read/development` 权限由主人自行确认；
- [ ] 主人、上游调度机器人和本地机器人的职责已经明确；
- [ ] 已约定回滚窗口和验收负责人。

存在未结束任务时不要切流。先让任务完成或由主人准确停止，并确认最终状态已回传原始来源。

## 阶段 1：离线准备原生版本

按照 [INSTALL.md](../INSTALL.md) 和 [SECURITY.md](../SECURITY.md) 完成依赖检查、固定版本构建和安全检查。

- [ ] `npm ci --prefix feishu-connector` 已完成；
- [ ] `./scripts/build-cc-connect-local.sh` 已构建固定版本并校验哈希；
- [ ] `npm test --prefix feishu-connector` 通过；
- [ ] `./scripts/release-check.sh` 通过；
- [ ] 原生配置仍未连接到正在被旧服务使用的同一飞书应用；
- [ ] Bridge 和 Management 未向局域网或公网开放。

新应用使用 `onboard-native.sh`：Agent 可以启动安装器，主人在浏览器和飞书界面批准，凭据与身份值自动写入私有配置。Agent 不得索取、代填或读取临时状态及生成后的配置正文。已有应用的手工恢复流程仍由主人在独立终端完成。

## 阶段 2：配置上游调度器

将 [上游调度器系统提示词模板](../config/aily-router.example.md)配置到 Aily 或其他上游智能体，并由主人填写非秘密占位项和工作区别名表。

确认调度器具备持久化状态，不只依赖大模型上下文：

```text
DS/T -> 来源会话、来源根消息、执行根消息、执行线程、状态、最终结果位置
```

验收以下规则：

- [ ] 新来源根链创建新 `DS` 和新执行根线程；
- [ ] 同一来源根链的后续任务沿用 `DS`、生成新 `T`；
- [ ] Aily 对同一 `DS` 使用持久 FIFO，一次只派发队首一个 `T`，不同执行根线程可并行；
- [ ] 同群两个独立话题不会被合并；
- [ ] 同一个 Aily 在不同群的任务不会共享会话；
- [ ] Aily 不代替主人批准工具、Git 或工作区；
- [ ] 停止前按 `T` 或引用关系找到唯一执行线程；
- [ ] 最终结果会回复到原始来源根消息/话题。

## 阶段 3：隔离 PoC

推荐使用独立测试飞书应用、测试执行群和无敏感数据的测试工作区。测试工作区可以是 Git 仓库，也可以是普通目录。

### 3.1 基础连接

- [ ] 启动原生 cc-connect 后能建立飞书长连接；
- [ ] 未在允许名单中的用户、机器人或群不能触发任务；
- [ ] 执行群中未明确 `@` 本地机器人的消息不会触发；
- [ ] 本地机器人能回复接收、排队、运行、等待审批和终态；
- [ ] 断连或执行失败会显示错误，不会静默丢失任务。

### 3.2 分流和内容

- [ ] 问候、测试、帮助和普通飞书操作由 Aily 自己处理，不产生本机 Agent 调用；
- [ ] 需要本机文件或终端的请求才生成 `[LOCAL_TASK]`；
- [ ] 文本任务可执行；
- [ ] 图片能被本地 Agent 实际读取，而不只是看到文件名；
- [ ] 文件能下载到受控临时位置并被实际读取；
- [ ] 链接在权限允许时能读取，权限不足时明确报错；
- [ ] 未配置语音转写时，语音消息明确提示未启用，不假装已经理解；
- [ ] 视频只显示元数据和可能的缩略图，不把它当作已读取视频正文；
- [ ] 不相关历史、附件和秘密不会被转交。

### 3.3 会话、排队和并行

依次构造以下场景并记录 `DS/T` 与执行线程：

| 场景 | 预期结果 |
|---|---|
| 同一来源根消息连续提出两个任务 | 同一 `DS`、两个 `T`；只派发 T1，T2 留在 Aily FIFO，T1 终止后再派发 T2 |
| 同群两个独立根消息各派发任务 | 两个 `DS`、两个执行线程、允许并行 |
| 两个不同群通过同一 Aily 派发 | 两个 `DS`、两个执行线程、允许并行 |
| 来源群中夹杂其他人的消息 | 不改变原有任务链归属 |
| 只说“继续”且存在多个候选任务 | Aily 先询问，不猜测目标 |

验证执行群中能看见 Aily 的排队通知，但通知没有 `@` 本地机器人，也不会提前触发 T2。cc-connect 自带等待队列只处理当前任务的补充消息，不承担独立 `T` 调度。

### 3.4 停止和取消

- [ ] 主人引用某个任务或给出唯一 `T` 后，Aily 能定位正确执行线程；
- [ ] 停止尚未派发的排队 `T` 时，Aily 只从自己的 FIFO 移除，不触发本地机器人；
- [ ] 停止活动 `T` 时，Aily 只在对应执行线程发送 `/stop`；
- [ ] 主人可以在对应执行线程直接停止；
- [ ] 停止一个任务不会停止其他执行线程中的任务，也不会丢失同一 `DS` 里尚未派发的任务；
- [ ] 多个候选任务时先列出候选并询问，不发送全局停止；
- [ ] 状态从 `stopping` 变为本地机器人确认的 `cancelled` 或实际终态；
- [ ] 停止结果回传到原始来源会话。

注意：原生 cc-connect 的停止语义是当前线程会话，不是跨线程的全局 `T` API；`/stop` 还可能清理线程内等待消息，`/cancel` 会重置整条会话。准确停止依赖 Aily 不把多个独立 `T` 同时派入本地线程。

### 3.5 审批和权限

- [ ] Aily 发起需要工具审批的任务时，任务进入 `waiting_approval`；
- [ ] 只有主人可以批准工具操作；如果上游另行分配 `PA-...`，它只用于追踪，不替代 cc-connect 的审批状态；
- [ ] Aily、其他机器人和其他用户尝试批准时均不生效；
- [ ] 历史批准不会被新任务复用；
- [ ] 未登记工作区保持暂停，不会把消息中的路径直接交给本地 Agent；
- [ ] 只读工作区不能执行开发写入；
- [ ] 开发任务在 Git 仓库中先确认分支；
- [ ] 确认分支后，具体 Git 命令仍逐条由主人批准；
- [ ] 非 Git 工作区可以正常完成适用任务，不会被强制初始化 Git。

本项目的固定版本补丁同时在 cc-connect 核心和飞书卡片回调层检查 `approval_from`。该项仍必须通过真人/Aily 分别点击和发送文字审批进行端到端验证，不能只凭单元测试判定切流成功。

### 3.6 结果回传

- [ ] 本地机器人的处理中、工具进度、失败和最终结果都引用原派发消息并 `@` 派发者；
- [ ] 主人直发任务时 `@` 主人，Aily 派发任务时 `@` 对应 Aily；
- [ ] Aily 根据 `DS/T` 把结果回复到正确的来源会话和来源根消息；
- [ ] 多个并行任务的结果不会串线；
- [ ] 失败、取消和等待输入也会回传，不只回传成功；
- [ ] 回传内容不包含密钥、完整个人路径、私密消息链接或内部日志。

## 阶段 4：受控切流

只有阶段 3 全部关键项通过后才切流。

1. 选择低风险时段，暂停新任务进入旧链路。
2. 确认旧链路没有运行中、排队中或等待审批的任务。
3. 停止旧 Connector/Bridge 服务并确认不再消费事件。
4. 运行自动安装器创建正式飞书应用，由主人完成浏览器授权、企业审批和群内配对；已有配置需要覆盖时先单独确认。
5. 启动原生 cc-connect，完成一次只读冒烟任务、一次媒体任务、一次 Aily 侧排队任务和一次准确停止。
6. 恢复上游 Aily 派发，并观察任务状态和结果回传。

同一个飞书应用绝不能同时连接旧 Connector 和原生 cc-connect。否则事件可能被不同连接竞争消费，表现为随机丢消息、状态错乱或重复执行。

## 阶段 5：观察期

建议在移除旧实现前保留一个观察期。观察内容只记录非敏感指标，不复制消息正文或日志：

- [ ] 派发任务数、成功数、失败数和取消数；
- [ ] 无响应、重复执行、跨线程串线和结果未回传次数；
- [ ] 图片、文件和链接的成功率；
- [ ] 错误审批人尝试是否均被拒绝；
- [ ] 未知工作区、权限不足和通道异常是否都会显式暂停或失败；
- [ ] 轻量请求没有进入本机 Agent。

观察期内旧代码可以保留，但旧服务保持停止，旧私有配置和会话不得纳入新部署或发行包。

## 回滚

遇到以下任一情况立即暂停新派发并回滚：

- 任务被错误线程执行或停止；
- Aily 或非主人可以批准工具/Git/工作区操作；
- 同一个 `T` 重复执行；
- 任务、错误或最终结果静默丢失；
- 允许名单、工作区或网络边界失效；
- 图片或附件处理导致越权读取或敏感信息外发。

回滚步骤：

1. 停止进入原生链路的新任务。
2. 对仍运行的任务逐线程确认状态；不要发送无上下文全局停止。
3. 停止原生 cc-connect，确认其不再消费飞书事件。
4. 恢复旧服务前确认原生连接已经退出，避免双连接。
5. 向原始来源回传受影响任务的实际状态。
6. 保留必要的非敏感故障摘要；私有日志、会话和附件仍留在本机，不复制到 Issue 或聊天。

回滚不等于删除原生配置或数据。删除、覆盖或清理必须另行获得主人明确批准。

## 阶段 6：完成迁移

观察期通过后：

- [ ] 将原生模式设为唯一生产入口；
- [ ] 更新运维文档和故障处理流程；
- [ ] 确认 Aily 的 `DS/T` 映射有持久化和备份策略；
- [ ] 确认服务托管方式不会依赖受管 Agent 会话；
- [ ] 由主人决定何时删除旧 Connector 私有配置、会话和运行数据；
- [ ] 删除前再次确认没有回滚需要，并使用可恢复方式处理。

代码仓库中可以暂时保留旧 Connector 作为兼容实现；正式删除应作为独立变更进行，不与首次切流混在一起。
