# 原生 cc-connect 模式

这是本项目的新推荐路径：直接使用 cc-connect 的官方飞书适配器，不再经过本项目旧版 `Feishu Connector -> Bridge` 链路。

```text
Aily（可选的前台分流）
        |
        | 在执行群中 @ 本地机器人
        v
飞书企业自建应用机器人 -> cc-connect 原生 Feishu -> Codex / Claude Code / Cursor Agent
```

当前目录提供三样东西：

- `dispatch-envelope.mjs`：Aily 或其他上游调度器可复用的任务封装和会话边界算法；
- `../config/cc-connect-native.example.toml`：原生飞书配置模板；
- `../scripts/onboard-native.sh`：通过官方 `PersonalAgent` 基座自动建飞书应用、申请权限、配对身份并生成私有配置；
- `../scripts/init-native-config.sh`：已有应用的高级恢复入口，新安装不需要手工使用。

安装器的 `--agent-type` 支持 `codex`、`claude` 和 `cursor`，仅把选择转换为 cc-connect 官方配置：`codex`、`claudecode` 或通用 `acp`。本项目不实现 Agent 会话协议，也不维护另一套路由器。若要同时运行多个执行器，应按 cc-connect 原生多项目/多机器人能力配置，而不是在一个项目中动态替换 Agent。

旧版 Connector 仍保留，便于从现有部署平滑迁移。不要让旧 Connector 和原生模式同时消费同一个飞书应用的长连接事件。

## 会话规则

Aily 为每个独立任务链生成一个 `DS-XXXXXXXX`，为其中每个具体任务生成一个 `T-XXXXXXXX`，并把任务放进执行群中独立的飞书根消息/回复线程。原生配置启用 `thread_isolation = true` 后：

- 同一 `DS` 由 Aily 维护持久 FIFO，同时只向同一线程派发队首一个 `T`；
- 当前 `T` 的补充信息可继续发到线程，独立的新 `T` 留在 Aily 队列，直到当前任务终止；
- 不同 `DS` 使用不同根消息线程，可以并行；
- 同一群里不同人的两段对话不能仅凭“同一个群”合并；
- 不同群默认也是不同任务链，即使使用同一个 Aily；
- 无法判断是续问还是新任务时，由 Aily 询问，不要猜测。

本项目的固定版本补丁会让群内文本、卡片、流式进度和最终结果同时引用原任务消息并 `@` 该消息的发送者。Aily 因此可以在自己的派发线程中接收终态、更新 `DS/T`，再把结果转回原始来源。该行为由 `mention_trigger_sender = true` 启用，私聊和机器人自身消息不会自动 `@`。

原生 cc-connect 的 `/stop` 停止当前线程会话，并可能清理该线程已接收的等待消息。因此 Aily 必须一次只派发一个 `T`：排队任务在 Aily 侧直接取消，正在运行的任务才在对应线程发送 `/stop`。跨线程没有原生全局 `T` API，精确定位依赖 Aily 持久化的 `DS/T -> 执行线程` 映射。

本项目的固定版本补丁新增 `approval_from`：核心层阻止非主人文字审批，飞书层阻止非主人点击工具审批卡片，并让所有卡片操作先通过 `allow_from`。启用策略后还会移除并拒绝“允许全部”，避免权限延续到同线程后续任务。空值保持上游兼容行为；本项目生成的原生配置始终显式填写主人。

`[LOCAL_TASK]` 中的工作区别名和 `read/development` 由 Aily 用来决策和暂停，不会自动改变 cc-connect 的 `work_dir` 或模式。安装参数只设置初始目录；之后主人可以使用原生 `/dir` 选择下一会话目录，Aily 无权切换。高级用户可自行启用原生 `multi-workspace`，本项目不重复维护工作区注册表。

## 媒体

原生 Feishu 适配器会下载图片和普通文件；链接按文本传递。语音需要单独配置语音转写，当前模板未启用；视频当前只有元数据和可能的缩略图，不支持读取视频正文。图片和文件暂存在工作区 `.cc-connect/` 下，本项目补丁会拒绝该路径中的符号链接/非目录，收紧既有目录为 `700`，并用随机排他文件名以 `600` 写入，避免同名覆盖。仍应限制附件大小，不要把密钥或私密聊天历史作为任务附件转发。
